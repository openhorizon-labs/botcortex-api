# botcortex-api

Cloud services for [BotCortex](https://github.com/openhorizon-labs/botcortex):
identity now; licensing, relay, and hub later. **Bun + Hono + Better Auth +
Drizzle**, with Supabase as the Postgres.

The on-robot runtime never depends on this service — an expired or unreachable
api can never stop motion or local execution.

## The two worlds

Authentication splits cleanly by caller, and the two never mix:

| Prefix | Caller | Credential |
|---|---|---|
| `/api/*` | the web app, through its Next rewrite | Better Auth session cookie |
| `/v1/*` | a runtime on someone's robot | robot key (`bx_live_…`) |

### Inference proxy

The authoring agent stays **on the robot**. These routes only let it reach a
model on BotCortex credits instead of the owner's own vendor account, so the
runtime opts in by swapping one `base_url`:

| Route | Shape | Runtime `base_url` |
|---|---|---|
| `POST /v1/chat/completions` | OpenAI | `<api>/v1` |
| `POST /v1/messages` | Anthropic | `<api>` |

Guards, in order: robot key → model must be in `src/pricing.ts` (an unpriced
model would meter to zero, so it is refused) → no streaming (usage arrives only
in the final SSE chunk) → balance > 0 → forward → record usage.

The cap is **soft by design**: checked before, debited after. A single call can
finish slightly negative, which beats killing a teach mid-authoring to save a
fraction of a cent.

### Credits

`credit_grant` minus `usage`, derived on read — never a stored running total, so
the balance can always be re-derived and every charge traces to its request.
Money is micro-dollars (1e-6 USD) as bigints; floats have no place in a ledger.

## Layout

| Path | What it is |
|---|---|
| `src/index.ts` | Bun entrypoint |
|  `src/hono.ts` | Hono app (createApp): CORS, `/health`, `/api/auth/*` (Better Auth), `/api/me`, then the two route groups |
| `src/routes/account.ts` | Session-authenticated: mint/list/revoke keys, credit balance |
| `src/routes/robot.ts` | Key-authenticated: inference proxy, skill sync, `/v1/me` |
| `src/pricing.ts` | Model allowlist + per-token prices — the only way a model becomes reachable |
| `src/credits.ts` | Ledger: balance, grants, usage |
| `src/keys.ts` | Robot-key minting, SHA-256 hashing, lookup |
| `src/auth.ts` | Better Auth config — email+password, Drizzle adapter |
| `src/auth-schema.ts` | Generated by `bun run auth:schema` — do not hand-edit |
| `src/app-schema.ts` | Everything Better Auth does not own — keys, credits, usage, skills |
| `src/schema.ts` | The union both drizzle-kit and db.ts point at |
| `src/db.ts` | postgres-js → Supabase pooler (`prepare: false`) |
| `drizzle/` | SQL migrations (`bun run db:generate`, apply with `bun run db:migrate`) |
| `tests/` | Full round-trip on in-memory Postgres (PGlite) — no network |

## Development

```bash
bun install
cp .env.example .env   # fill DATABASE_URL + BETTER_AUTH_SECRET
bun test               # runs against PGlite, no Supabase needed
bun run dev            # http://localhost:8787
```

Schema changes: edit `src/auth.ts` → `bun run auth:schema` → `bun run db:generate`
→ apply the new `drizzle/*.sql` to Supabase.

## Deploy (Vercel)

`api/index.ts` is the Vercel entrypoint (**Node.js runtime** — the TCP Postgres
driver rules out Edge); `vercel.json` rewrites every path to it. Import the repo
in Vercel and set: `DATABASE_URL` (Supabase pooler URI), `BETTER_AUTH_SECRET`,
`BETTER_AUTH_URL` (the deployed URL), `TRUSTED_ORIGINS` (app origins), and the
vendor keys the proxy spends — `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`. Those two
are **ours**; robots authenticate with `bx_live_` keys and never see them. A
missing one 503s that provider's route and nothing else.

Provision waitlisted users (no public sign-up UI):

```bash
DATABASE_URL=… bun scripts/create-user.ts owner@lab.dev 'password' "Name"
```
